# Desarrollo

Cómo está hecha la Biblioteca de traducciones y cómo compilarla. Lo que hace el programa está en el [README](README.md).

Está hecha con [Tauri 2](https://tauri.app): el motor en Rust (`src-tauri/`) y la ventana en HTML, CSS y JavaScript sin frameworks (`ui/`). De RecompLauncher solo toma la idea general; el código es propio.

## Cómo funciona

| Qué | Dónde |
|---|---|
| Catálogo | Va dentro del programa, en `src-tauri/recursos/catalogo`: `traducciones_fan.csv` (las traducciones) y `centro_datos.json` (portadas, descargas directas y AppID de Steam de cada ficha) |
| Catálogo al día | `catalogo.rs`. Al abrir, y luego cada seis horas (`catalogo_al_dia` en `lib.rs`), compara el sha de git de esos dos ficheros con los de la rama `main` de este repositorio (API de GitHub). Si son otros, baja los nuevos a `<datos>\catalogo`, comprueba su sha y que se leen bien, y la ventana los recarga. Una versión nueva del programa vuelve a usar el suyo. El botón «Buscar actualizaciones» de Ajustes (comando `buscar_actualizaciones`) hace esa misma comprobación a mano junto con la de versión nueva del programa. Las portadas a mano que aún no lleva dentro el programa se traen de `ui/portadas` del repositorio |
| Ventana | `ui/app.js`. Junta las fichas en juegos (mismo sistema y título, o mismo AppID de Steam), empareja tus juegos con las traducciones (por CRC32, por AppID o por el nombre) y pinta las secciones |
| Buscar tus juegos | `escaneo.rs`. Saca el CRC32 de cada ROM, lee el índice de los .zip sin descomprimirlos y usa 7-Zip para los .7z y .rar. Guarda una caché para que las siguientes búsquedas vayan rápidas. Los juegos de PC salen del registro y los manifiestos de Steam, GOG y Epic |
| Bajar el parche | `descarga.rs`. Solo de Traducciones Wave, archive.org y GitHub (también la API de versiones de GitHub), comprobando cada redirección. De los paquetes de RetroAchievements saca solo los ficheros de la ficha |
| Aplicar el parche | `parcheo.rs` y `motor.rs`. Comprueba por CRC32 que tu juego es la versión que pide la traducción, también sin la cabecera de NES o de SNES. Saca el juego de su .zip/.7z/.rar o de su .chd y monta el disco traducido en un .chd. IPS, BPS, UPS, PPF y APS los aplica el propio programa; xdelta, el `xdelta3.exe` que lleva dentro, igual que 7-Zip y chdman |
| Trabajos | `trabajos.rs`. Una cola: buscar juegos y traducir, de uno en uno. Vigila la carpeta Descargas cuando una traducción no tiene descarga directa |
| Portadas propias | `portadas.rs`. Las imágenes se copian a `portadas\` en tus datos y se apuntan en `portadas_propias.json`; la ventana las ve con el protocolo `asset` de Tauri |
| Favoritos y listas | `listas.rs`. Se guardan en `listas.json` en tus datos: cada juego con su clave de juego (la misma con la que la ventana junta sus traducciones) y la traducción que tenías elegida. La ventana manda siempre todas las listas juntas y aquí se limpian (Favoritos siempre existe y va la primera) |
| Estadísticas de uso | `uso.rs`. Al minuto de abrir y luego cada seis horas (`uso_al_dia` en `lib.rs`), como mucho una vez al día y solo después de la bienvenida, pide `https://stats.bibliotecadetraducciones.com/count?p=app/<versión>&e=true`: en GoatCounter sale como el evento `app/<versión>`, y sus visitantes de cada día son las personas que lo han abierto. El día del último aviso queda en `uso.txt` en tus datos. El User-Agent lleva un espacio (`Biblioteca-de-traducciones/<versión> (Windows)`) porque GoatCounter toma por robots, y no cuenta, los que no lo tienen. Se quita con la casilla de Ajustes (`estadisticas` en `ajustes.json`) |
| Tus datos | `%LOCALAPPDATA%\es.traducciones.biblioteca`: trabajos y su registro, parches descargados, la lista de tus juegos, tus portadas y tus listas |
| Ajustes | `%APPDATA%\es.traducciones.biblioteca\ajustes.json`. Si no existe, la ventana da la bienvenida y pregunta dónde están los juegos |

Las portadas se prueban en orden hasta que una carga: la tuya, la elegida a mano para el catálogo (va dentro del programa, en `ui/portadas`), la de libretro-thumbnails (por el nombre No-Intro o Redump) o la de Steam, la de la base de datos pública de LaunchBox y la pantalla de título.

## Compilar

Hace falta Node.js, Rust (`rustup`, versión estable) y las herramientas de C++ de Visual Studio (Build Tools 2019 o posteriores).

```bash
npm install
npm run build:prueba                  # prueba rápida: src-tauri\target\debug\biblioteca-traducciones.exe
npm run build                         # instalador: src-tauri\target\release\bundle\nsis\
```

Compila siempre con `npm run build`, que llama a `tools\compilar.ps1`, y no con `npx tauri build` directamente. Ese script le dice al compilador que cambie por nombres genéricos las rutas de tu máquina (tu carpeta de usuario, la de Rust y la del proyecto). Si no, el `.exe` las lleva dentro.

Al publicar una etiqueta `v*` en GitHub, GitHub Actions compila el instalador, lo firma (ver abajo) y lo sube a la versión (`.github/workflows/publicar.yml`).

## Firma del instalador

El instalador saldrá firmado con el certificado de [SignPath Foundation](https://signpath.org), que firma gratis programas de código libre compilados en GitHub Actions, cuando acepten el proyecto. **Estado:** solicitado en noviembre de 2026 y denegado por falta de visibilidad (miran estrellas, forks, colaboradores, artículos y hilos en Reddit o YouTube); invitan a volver a pedirlo en <https://signpath.org/apply> cuando el programa tenga difusión. Su plan de pago (500 $ al año) solo da certificados a empresas registradas. Al pedirlo otra vez, el README tiene que llevar en «Code signing policy» las frases que exigen, tal como estaban en el commit 42be214: la atribución «Free code signing provided by SignPath.io, certificate by SignPath Foundation», los roles del equipo (committers and reviewers, approvers) y la frase de privacidad «This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it».

SignPath no firma dentro de instaladores NSIS, así que se firma el instalador entero y el `.exe` del programa que va dentro queda sin firmar (ver Pendiente). Las condiciones están en <https://signpath.org/terms>: licencia libre, doble factor en GitHub y en SignPath, la sección «Code signing policy» del README y aprobar cada firma a mano.

El flujo `publicar.yml` lo hace así: guarda el instalador como artefacto del flujo (`actions/upload-artifact`), lo manda a firmar (`signpath/github-action-submit-signing-request`), espera a que alguien del proyecto apruebe la petición en signpath.io (**media hora como mucho**; si se pasa, el trabajo falla y se vuelve a lanzar con `gh run rerun --failed <id>`) y sube el instalador firmado a la versión. Si en el repositorio no está la variable `SIGNPATH_ORGANIZATION_ID`, se salta la firma y sube el instalador sin firmar, como antes.

Lo que hay que tener configurado:

- En el repositorio (Settings › Secrets and variables › Actions): el secreto `SIGNPATH_API_TOKEN` (token de API de un usuario de SignPath con permiso de *submitter*) y las variables `SIGNPATH_ORGANIZATION_ID`, `SIGNPATH_PROJECT_SLUG` y `SIGNPATH_SIGNING_POLICY_SLUG` (la política de firma de versiones, normalmente `release-signing`).
- En SignPath: el sistema de compilación de confianza *GitHub.com* añadido a la organización y enlazado al proyecto; el proyecto enlazado a este repositorio; y esta configuración de artefacto, que exige que el fichero firmado lleve el nombre del programa y la versión que le pasa el flujo:

```xml
<artifact-configuration xmlns="http://signpath.io/artifact-configuration/v1">
  <parameters>
    <parameter name="version" required="true" />
  </parameters>
  <pe-file product-name="Biblioteca de traducciones" product-version="${version}">
    <authenticode-sign />
  </pe-file>
</artifact-configuration>
```

En las notas de cada versión conviene poner el enlace a la política: `Instalador firmado por SignPath Foundation: [Code signing policy](https://github.com/alucardog-dotcom/biblioteca-traducciones#code-signing-policy)`. Y cuando salga la primera versión firmada, quitar del README la nota «estamos en ello» y el aviso de que el instalador no está firmado.

## Pruebas

`cargo test` en `src-tauri`. Las pruebas crean juegos y parches inventados y comprueban cada formato, las cabeceras de NES y SNES, los comprimidos y los discos .cue/.bin y .chd con xdelta. Usan las herramientas de `src-tauri/recursos/herramientas`.

Para inspeccionar la ventana abierta, arranca el programa con `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` y conéctate a ese puerto con las herramientas de desarrollo de Chrome o Edge.

## El catálogo

El catálogo se mantiene aparte, con unos scripts de Python que todavía no están en este repositorio. Leen los listados de cada fuente y generan `traducciones_fan.csv` y `centro_datos.json`. `tools/preparar_recursos.py` copia el resultado dentro del programa:

- el catálogo, a `src-tauri/recursos/catalogo`;
- las portadas elegidas a mano, a `ui/portadas`;
- 7-Zip, chdman y xdelta3, a `src-tauri/recursos/herramientas`.

Las portadas que alguien pone a mano en el programa pueden pasar al catálogo para que las vea todo el mundo. Se guardan por clave de juego, la misma con la que la ventana junta las traducciones (`claveJuego` en `ui/app.js`).

Para poner al día el catálogo de todos basta con subir a `main` los ficheros nuevos de `src-tauri/recursos/catalogo` (y las portadas de `ui/portadas`): los programas ya instalados los descargan al abrirse, cada seis horas o al pulsar «Buscar actualizaciones». No hace falta publicar una versión.

## La web

`tools/web.py` genera la web a partir del catálogo: la portada, el buscador (`web/catalogo.js`, que lee `catalogo/juegos.json`), una página por juego y otra por sistema, más `sitemap.xml` y `robots.txt`. Junta las traducciones en juegos y elige las portadas igual que la ventana. Solo usa la biblioteca estándar de Python:

```
python tools/web.py          (la deja en _web; para verla: python -m http.server -d _web)
```

Las páginas de los juegos de PC que están en Steam (los que tienen AppID) llevan un enlace a su página de la tienda de Steam, sin afiliado (`en_steam` en `tools/web.py`). La ficha del programa lo enseña también cuando no tienes el juego (`enSteam` en `ui/app.js`). La web y el programa no llevan enlaces de afiliado ni piden donaciones.

Los juegos de PC que no están en Steam pero tienen página oficial conocida (itch.io, Game Jolt o la web de su autor; campo `pj` del catálogo, con `pj18` si es para adultos) llevan en su lugar un enlace a esa página, también en el programa cuando no tienes el juego.

Las traducciones de PC y de las consolas actuales (Switch, PS3, PS4, Xbox 360…; `MODERNAS` en `ui/app.js` y en `tools/web.py`) se instalan a mano: ni la web ni el programa las marcan como «Un clic» aunque su descarga sea directa.

El flujo `web.yml` la genera y la publica en GitHub Pages cada vez que cambia en `main` el catálogo, las portadas a mano, las capturas o la propia web.

**IndexNow** (08-11-2026): Bing, y con él DuckDuckGo, Ecosia, Yandex y otros, se entera de las fichas nuevas por [IndexNow](https://www.indexnow.org/). La clave es `web/<32 cifras hexadecimales>.txt`, con la misma clave dentro, y tiene que estar en la raíz de la web; `web.py` no la copia. Por eso `web.yml`, antes de subir la web, llama a `tools/indexnow.py --preparar`, que pone la clave en `_site` y guarda el `sitemap.xml` publicado. Después de desplegar llama a `tools/indexnow.py --anterior`, que compara los dos sitemaps y manda a `api.indexnow.org` las direcciones nuevas o con otro `lastmod`, más la portada, `/catalogo/` y `/novedades/` (10.000 por envío como mucho). Los dos pasos llevan `continue-on-error`: si fallan, la web se publica igual. Las fichas sin fecha en el sitemap (unas 1.800) solo se avisan cuando son nuevas. En local, después de `python tools/web.py`, `python tools/indexnow.py --sin-enviar` dice cuántas mandaría, y `--todas` manda todas las del sitemap. El alta en Bing Webmaster Tools, que puede importar el sitio desde Search Console, va aparte.

**Títulos y descripciones para los buscadores** (09-11-2026): los títulos ya no llevan «· Biblioteca de traducciones» (Google enseña el nombre de la web encima de cada resultado, con `og:site_name` y el `WebSite` de la portada, que lleva `alternateName` porque la Biblioteca Virtual Miguel de Cervantes tiene dos portales que se llaman casi igual). Cada ficha se titula como se busca: «Chrono Trigger en español (SNES): parche de traducción», con el nombre corto del sistema (`SIS_CORTO`) y, si no cabe en `MAX_TITULO` (65), sin la coletilla, pero nunca sin el sistema; dos juegos distintos con el mismo nombre en el mismo sistema llevan el año (`repetidos` en `main()`). Las descripciones se arman de la más completa a la más corta (`el_mas_largo_que_quepa()`) hasta caber en `MAX_DESC` (158), quitando primero grupos y luego el año y el estado. Mis listas y la 404 llevan `noindex`. La portada de cada ficha va con `fetchpriority="high"` y `preconnect` a su servidor, porque es lo más grande que se ve al abrirla. `/parchear/` lleva debajo de la herramienta cómo parchear una ROM, los formatos y unas preguntas, para que tenga texto que los buscadores puedan leer.

Los botones «Descargar» de la web bajan el instalador directamente: enlazan a `releases/latest/download/Biblioteca-de-traducciones-setup.exe`, y `publicar.yml` sube el instalador solo con ese nombre fijo (hasta la 0.7.8 lo subía también con el nombre con versión, y en la página de la versión salían dos ficheros iguales). La versión se ve en la página de la release y en Ajustes › Acerca de; el SHA-256 lo enseña GitHub junto al fichero.

**Parchear en el navegador** (`/parchear/`, prueba desde el 07-11-2026): la web también aplica traducciones sin el programa. `web/motor.js` es `motor.rs` pasado a JavaScript (IPS, BPS, UPS, PPF 1 a 3 y APS de N64 y GBA, con las mismas comprobaciones; CRC32 y lectura de zips con `DecompressionStream`, sin librerías) y `web/parchear.js` hace el resto: lees la ROM (o un zip con ella), calcula su CRC32 con y sin cabecera (16 bytes iNES, 512 de copiador de SNES), la busca en `catalogo/parches.json` (lo escribe `parches_json()` en `web.py`: cada traducción con sus CRC y sus descargas, como `centro_datos.json`), baja el parche con `fetch` (Wave, archive.org y raw.githubusercontent envían `Access-Control-Allow-Origin: *`; las releases de GitHub se resuelven por su API), lo aplica y ofrece el traducido para descargarlo o guardarlo con `showSaveFilePicker` (Chrome y Edge). Todo ocurre en el navegador: el juego no se sube a ningún sitio. No cubre xdelta ni 7z, rar y CHD, que siguen necesitando el programa. La misma página tiene «elegir carpeta» (un `input` con `webkitdirectory`): `escanear()` en `parchear.js` hace lo que `escaneo.rs`, con sus mismas tablas de extensiones y nombres de carpeta: CRC32 de cada ROM por trozos (`file.stream()`, con y sin cabecera iNES o de copiador), el de los ficheros de un zip leído de su índice (solo el final del fichero; si la única ROM del zip lleva cabecera, se saca para el CRC sin ella) y el de las pistas de los .cue y .gdi; después empareja por CRC (exacto) o por el nombre (posible, con `tokens`/`simil` de app.js, umbral 0,8) contra `parches.json`, que por eso lleva también `r` (rom_requerida), y pinta los juegos con traducción como tarjetas (portada de `juegos.json`) con el botón Traducir, que lee ese fichero y sigue el mismo recorrido. Las pruebas del motor en Node (los mismos casos que `motor.rs`), el fichero con CRC forjado y la carpeta de prueba (ROMs falsas con el CRC de fichas reales, con cabeceras, en zip y un .cue) están en el scratchpad de la sesión que lo hizo.

**Favoritos y listas en la web** (07-11-2026): `web/listas.js` va en todas las páginas (lo mete `pagina()`), guarda en `localStorage` (`listas`: `{v, listas: [{id, nombre, juegos: [{r: ruta de la ficha, t, s, sn, p: hasta tres portadas absolutas}]}]}`, la primera es `fav`) y pinta el corazón de cada tarjeta (las de `tarjeta_juego()`, las del buscador y las de Mis juegos llevan `data-ruta`, `data-sis`, `data-sisn` y `data-titulo`; un observador marca las que llegan después), el menú «Guardar en una lista» de la ficha (`.juego-acciones`, con `data-port` para las portadas), la fila «Tus favoritos» de la portada (`#favoritos-inicio`) y la página `/mis-listas/` (`pagina_listas()`: listas con sus juegos, quitar, renombrar, borrar, crear, y copia en JSON para llevarlas a otro navegador, que al restaurar se junta con lo que haya sin repetir). Sin cuentas ni servidor: lo que cada uno guarda se queda en su navegador. Cuántas veces se guarda cada juego: la ficha lo dice en cuanto hay uno (`FAVORITOS_MIN`, 1 desde el 13-11-2026; antes, 3). La cifra es la de partida de `web/favoritos_base.json` (hasta `FAVORITOS_DESDE`) más lo que cuenta GoatCounter desde entonces (`favoritos_fichas()`), y `favoritos_sin_bajar()` la publica en `favoritos.json` para que nunca baje. Con esas cifras sale «Los más guardados en Favoritos» (`MAS_FAVORITOS`, `/selecciones/mas-favoritos/`, sin juegos para adultos), que va en Selecciones junto a «Lo más visto» y con sus seis primeros en la portada.

**Novedades del catálogo** (08-11-2026): la portada abre con el buscador y «Últimas novedades», y `/novedades/` lista por días lo que ha entrado en el catálogo (también como canal Atom en `/novedades.xml`, enlazado en la cabecera de todas las páginas). La fecha de alta de cada ficha sale del historial de git del CSV (`fechas_alta()` en `tools/web.py`: mira los commits de los últimos `DIAS_NOVEDADES` días, 120, y las filas que ya estaban en el más antiguo no cuentan; si en un commit una fila cambia de grupo para sumar autores, como al acreditar a shadowman1 el 08-11-2026, conserva su fecha y no sale como nueva), por eso `web.yml` hace el checkout con `fetch-depth: 0`; sin historial (un clon superficial) la portada enseña las últimas traducciones por su fecha. Los juegos para adultos no salen en la portada ni en el canal; en `/novedades/` van ocultos como en el catálogo. El programa para Windows queda en la portada como un bloque más, después de las novedades y los sistemas. Al lado del buscador va un **mosaico de nueve portadas** (`destacados()`): primero los juegos fijados en `web/destacados.txt` (sistema|título), luego hasta cuatro novedades de los últimos días con tirón de 60 o más y, para completar, los juegos de más tirón del catálogo barajados por día; sin IA ni adultos, con portada, dos por sistema y tres por familia como mucho. El **tirón** (0-100) está en `web/popularidad.tsv` y lo calcula `herramientas\mantenimiento	iron.py` con los votos de la comunidad de LaunchBox (`popularidad_launchbox.py` sobre Metadata.xml, `cache\popularidad_launchbox.tsv`), las reseñas de Steam (`steam_tiron.py`, appdetails de store.steampowered.com, `cache\steam_tiron.tsv`) y una propina por ser proyecto de TraduSquare o tener varias traducciones; hay que volver a pasarlo cuando entren juegos nuevos. La clave para seguir una ficha por el historial va sin acentos ni signos (`clave_fila`), para que una corrección de mayúsculas no la convierta en novedad.

**Para todos los hispanohablantes** (08-11-2026, tras quejas de usuarios latinos): la web no dice «castellano» ni enseña la bandera de España. La franja es un degradado, el logotipo es el cartucho con las iniciales BT (ver «Logotipo»), los textos hablan de traducciones «de España y de toda Latinoamérica» y las fichas dicen «al español» a secas, o «al español (latino)», «(neutro)» o «(de España)» cuando `variante()` lo saca de las notas o del grupo. Esa variante va como chip en cada traducción y como filtro «Español latino» en el catálogo (bit 16 de `banderas()`). Queda pendiente una columna `variante` en el catálogo para no depender de las notas.

**Logotipo** (12-11-2026, elegido por el usuario): un cartucho rojo (#B11F2A) con las iniciales BT, la B roja y la T dorada (#E2A800), sobre blanco. El SVG (`web/icono.svg`, igual que `ui/icono.svg` y el `icono.svg` del README) está dibujado a mano sobre la imagen que dio el usuario, con el cartucho relleno de blanco para que se vea sobre fondo oscuro. De él salen `web/apple-touch-icon.png` (180 px, fondo blanco), `web/favicon.ico`, los avatares de foro de `web/img/avatar/`, los iconos del programa (`npx tauri icon` sobre un PNG de 1024 px; solo se copian los ficheros que ya había en `src-tauri/icons/`, sin los de Android ni iOS), la vista previa `web/img/vista-previa.png` (sale de `promocionista-previa-github.html` con la dirección de la web; luego se tapan los subtítulos de grupo de la captura, y 379-394) y la foto de perfil de X (`promocionvatar-x-400.png`, con el logotipo al 68 % porque X la recorta en círculo). La web y el programa usan el rojo y el dorado del logotipo: `--rojo` y `--amarillo` en `web/estilo.css`, `--acc` y `--acc-2` en `ui/app.css`.

**Doblajes** (08-11-2026): las traducciones con voces en español llevan en sus notas una frase fija (`RE_DOBLAJE` en `tools/web.py`: «Doblaje al castellano.», «Traducción y doblaje al español latino.», «Doblaje parcial al…»; la regla está en `catalogo\LEEME_catalogo.txt`). `doblaje()` distingue las que solo ponen voces a un juego que ya tenía los textos en español de las que traducen y doblan. Con eso, la web enseña el chip «Doblaje» o «Con doblaje» en cada traducción, cambia el título, la entradilla y el resumen de la ficha («Lies of P (PC): doblaje al español»), tiene el filtro «Doblajes» en el catálogo (bit 32 de `banderas()`), la página `/doblajes/` con los dos apartados y un bloque en la portada con los seis de más tirón. TraduSquare marca el doblaje en cada proyecto con la barra «Doblaje 100 %»: `tradusquare_fichas.py` lo lee y `tradusquare_filas.py` escribe la frase.

**Fichas completas, grupos, selecciones y en camino** (08-11-2026):

- **El juego.** `web/datos_juegos.json` (de `herramientas\mantenimiento\datos_launchbox.py` sobre el Metadata.xml de LaunchBox) da a cada ficha año, desarrolladora, editora, géneros, jugadores, enlace a la Wikipedia, vídeo de YouTube y capturas. La ficha escribe su propia descripción con esos datos (`descripcion_juego()`; las «Overview» de LaunchBox son casi siempre texto de la Wikipedia o de las editoras y no se copian), enseña hasta cuatro capturas rotuladas como del juego original y un vídeo que no se carga hasta que se pulsa (`yt()`, youtube-nocookie). Hay que volver a pasar el script cuando entren juegos nuevos. Desde el 11-11-2026, `datos_steam.py` completa ese fichero con la tienda de Steam (`appdetails`, guardado en `cache\datos_steam.json`) para las fichas de PC con AppID que LaunchBox deja sin capturas: hasta cuatro capturas («steam:<AppID>/<nombre>» en `s`; `captura()` les pone la dirección, y van rotuladas como de su página de Steam) y, si LaunchBox no da nada, año, desarrolladora, editora y géneros, con `o: steam`. Esos géneros solo se usan en el texto de la ficha: son muy amplios y `de_genero()` no los cuenta para las selecciones. Los juegos para adultos no llevan capturas de Steam. `completar_fichas.py` lo pasa después de `datos_launchbox.py`, que también lo llama al acabar (sin red, desde la caché) para no borrar lo de Steam.
- **Grupos.** Cada grupo o traductor con `MIN_GRUPO` (3) traducciones o más tiene `/grupo/<nombre>/`, con sus traducciones por sistema y las webs donde publica (los dominios que más repiten sus fichas, sin sitios de descargas ni foros); `/grupos/` es el índice. «A / B» cuenta para los dos (`partes_grupo()`, con alias en `GRUPO_ALIAS`), y el nombre del grupo en cada traducción enlaza a su página.
- **Logros.** `tiene_logros()`: la traducción tiene versión en RAPatches (RetroAchievements). Chip «Logros», filtro «Con logros» (bit 64) y selección propia.
- **Selecciones.** `/selecciones/` con imprescindibles por sistema (`SISTEMAS_IMPRESCINDIBLES`) y por género (`SELECCIONES_GENERO`: RPG japoneses, aventuras, novelas visuales, terror…), ordenadas por tirón y sin los juegos que solo tienen traducciones con IA. «La selección del bibliotecario» (`SELECCION_MANO`, `/selecciones/seleccion-del-bibliotecario/`) es la de quien lleva la web: los juegos de `web/seleccion.txt` (`sistema|título` tal como está en el catálogo, uno por línea), todos, también los que solo tienen traducción con IA, barajados cada día; va en su propio bloque, «Elegidos a mano», y entra en la rotación de «Explora». Si un juego de la lista ya no está en el catálogo, `web.py` lo avisa al generar.
- **Contacto.** Desde el 11-11-2026 la web manda los avisos (errores, traducciones que faltan, autores que quieren cambiar o retirar su ficha, traducciones perdidas que alguien conserva) al correo de contacto, `CORREO` en `tools/web.py`, y ya no a las incidencias de GitHub, que piden cuenta: `contacto()` hace el enlace con el asunto ya puesto (en cada ficha, el nombre del juego) y `mailto()`, el de «La tengo», con el texto escrito. Va también en el pie de todas las páginas, junto al enlace a la cuenta de X (`X_CUENTA`).
- **En camino.** `/en-camino/` junta los proyectos en curso de TraduSquare (`web/en_camino.json`, de `herramientas\mantenimiento\en_camino.py`, que lee su listado una vez; conviene pasarlo de vez en cuando) y las traducciones del catálogo en beta, parciales o en curso.
- **La web antes que el programa, cuando puede.** En las fichas de juegos retro el botón principal depende de dónde se aplica la traducción (`donde_aplicar()` en `tools/web.py`): «Traducir en el navegador» si alguna es IPS, BPS, UPS, PPF o APS (lo que aplica `web/motor.js`), y «Cómo jugarlo» empieza por Parchear en el navegador, que ya escanea una carpeta entera (`#mi-carpeta`, enlazado desde la portada); «Traducir con el programa para Windows» si son xdelta, con una línea que explica que el navegador aún no los aplica; e «Ir a la traducción» si son archivos, mods o instaladores. Sin formato apuntado decide el sistema: en los de cartucho casi todo es IPS y se ofrece el navegador; en los de disco o de ROMs grandes (`DISCO`: PS1, PS2, PSP, Dreamcast, Saturn, NDS, 3DS…), donde el formato conocido más común es xdelta, el programa. Así se vio en GoatCounter el 10-11-2026: casi todos los que llegaban a Parchear desde una ficha venían de juegos de disco con parches xdelta. Los eventos `parchear/reconocido` y `parchear/traducido` dicen si funciona.

Las estadísticas de la web van con [GoatCounter](https://www.goatcounter.com/) (gratuito para webs sin ánimo de lucro, sin cookies, por lo que no hace falta aviso de cookies): en `tools/web.py`, la constante `GOATCOUNTER` lleva el código del sitio (lo que va antes de `.goatcounter.com`); vacía, la web no carga ningún script. Cuenta las páginas vistas, de dónde viene la gente y los clics en los botones de descarga (`data-goatcounter-click`). Como las listas de los bloqueadores de anuncios (EasyPrivacy) cortan gc.zgo.at y goatcounter.com como terceros, el script va dentro de la web (`web/estadisticas.js`, el count.js de GoatCounter, licencia ISC; conviene refrescarlo de vez en cuando) y las visitas se mandan a `stats.bibliotecadetraducciones.com`, un CNAME en Nominalia a `bibliotecadetraducciones.goatcounter.com` que también está en los ajustes de GoatCounter como dominio propio (`GOATCOUNTER_DOMINIO` en `web.py`). GoatCounter avisa de que eso no engaña a todos los bloqueadores (Firefox con uBlock mira a dónde apunta el CNAME), así que el recuento siempre va por debajo del real; las descargas de GitHub sí son exactas. Las descargas totales de cada versión las cuenta GitHub (`gh api repos/alucardog-dotcom/biblioteca-traducciones/releases --jq '.[] | {tag_name, assets: [.assets[] | {name, download_count}]}'`), y las búsquedas con las que aparece la web, Google Search Console. El dominio es `bibliotecadetraducciones.com` (comprado en Nominalia el 07-11-2026, con `bibliotecadetraducciones.es`; renuevan el 07-11-2027). Está en `web/CNAME` (de ahí lo leen `web.py` y `preparar_centro.py`, que pone esa dirección en las miniaturas del catálogo) y en Settings › Pages del repositorio. En Nominalia, el `.com` lleva los registros de GitHub Pages: cuatro A en la raíz (185.199.108.153, 185.199.109.153, 185.199.110.153 y 185.199.111.153), sus cuatro AAAA (2606:50c0:8000::153 a 2606:50c0:8003::153) y `www` como CNAME a `alucardog-dotcom.github.io`; el `.es` solo redirige al `.com`. La dirección antigua de GitHub Pages redirige sola al dominio.

Todas las páginas llevan `<meta name="referrer" content="strict-origin">` (09-11-2026): al pasar de una página de la web a otra, el navegador solo dice que se viene de `bibliotecadetraducciones.com`, sin la ruta. Sin eso, cada página de la web contaba en GoatCounter como un referrer distinto; el panel coge los 24 primeros (con «Cantidad» 6), quita los del propio dominio y se quedaba con dos o tres de fuera, sin «Ver más». A las otras webs les llega lo mismo que antes, solo el dominio. Para saber cuántas visitas trae un anuncio, aunque llegue desde una app que no manda el origen (la de Reddit, Discord, WhatsApp), el enlace lleva `?ref=<etiqueta>` (`?ref=reddit-mx`): GoatCounter lo toma como referrer.
